02 / 八维标准

少猜一点。
少绕一圈。

检查代码让接手者额外寻找、记住和重建什么。
行数、函数数量和异常数量，都不能单独决定质量。

D1

命名与含义

+

对照名称、完整职责和使用位置，检查角色、单位、领域概念与同词多义。短名称放在实际语境里判断。

D2

主流程与控制流

+

从入口跟随主要路径，观察阶段、分支和退出点。检查防御与适配是否反复打断正常阅读。

D3

数据与状态表达

+

追踪关键数据的建立、更新和使用。检查隐含位置协议、分散状态和不易发现的副作用。

D4

抽象与职责

+

一起读调用者与实现，判断边界隐藏了哪些有用细节，又让调用者学习了哪些额外约定。

D5

共享规则与局部修改

+

确认重复的是同一知识，定位定义和使用点。比较集中来源的收益与新增协议成本。

D6

机制的直接性与必要性

+

根据实际任务、输入边界和已有保证，判断检查、包装、重试与回退的用途和理解成本。

D7

注释与文档的信息价值

+

查看文字是否补充原因、背景与接口约定，重要信息是否容易找到，语法复述是否盖住重点。

D8

局部表达与逻辑分段

+

检查表达式、相关语句和阅读顺序。中间变量、紧凑语法与留白应当帮助辨认关系。

0—3 分，逐维度报告。评价可读性与结构维护成本，功能验收另外处理。
